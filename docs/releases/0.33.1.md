# Aru Host 0.33.1

这一版修 VPS 升级、Host 版本上报、无桌面 Linux 上的模型 API Key 存储，以及 Node.js 18 上无法新建电脑协作者的问题，没有新功能。协议仍为 `stub-0.30`，对话和协作者数据没有迁移。

- `sudo aru-selfhost upgrade` 现在会升级到最新的正式版。之前它会重装安装时记下的那个版本或安装包，看起来升级成功，其实版本没变。`upgrade --ref REF` 只对这一次生效，不会把以后的升级固定在 REF 上。
- 查不到最新正式版或下载失败时，保持当前安装不变。安装中途失败时，恢复原来的配置文件和版本指针，数据不动。
- VPS 安装也会写入版本信息，手机可以显示这台 Host 的版本并和最新版比较。之前 VPS 上的 Host 不上报版本，手机只能显示「版本未知」。
- 无桌面的 Linux（VPS）改为把模型 API Key 加密存放在 `/var/lib/aru-selfhost/provider-secrets`，由 Host 服务自己管理，不再依赖桌面的 Secret Service。第一次启动时会从原来的位置导入一次，导入不了的 Key 会在对应的模型配置上提示你重新填写，协作者、配置和对话都保留。
- 新增 `sudo aru-selfhost reset-provider-keys`：只在原来的密钥彻底找不回来时使用。它会清空已保存的 API Key，保留配置、协作者和对话，之后在手机上重新填 Key 即可。
- 桌面版（macOS、Windows、Linux 桌面）的 Key 存储方式不变。
- 修复 Host 跑在 Node.js 18 上时，手机新建电脑协作者提示「internal error」、执行方式列表一直为空的问题。原因是查询 Codex 驱动状态时用到了 Node 18 没有的 `WebSocket`；现在 Node 18 上可以正常列出并使用模型 API 执行方式，Codex 仍需要 Node.js 22。

## 与手机端的配套

- Aru 0.3 (202609250159) 会把外部触发器绑定到具体的 Host。旧触发器如果无法确认属于哪台 Host，手机上会提示「重新连接 Host」，重连后原有对话和触发器内容都在。这一步在手机上完成，不依赖这一版 Host。
- Host 和手机谁先更新都可以。

## 下载与升级

桌面版直接安装新版，无需先卸载。

VPS 运行 `sudo aru-selfhost upgrade`。如果升级后版本还是没有变化（旧的升级脚本会一直重装原来记下的版本），运行一次下面的命令，之后正常升级即可：

```bash
curl -fsSL https://raw.githubusercontent.com/Aevella/aru-host/main/upgrade.sh -o /tmp/aru-host-upgrade.sh
sudo bash /tmp/aru-host-upgrade.sh
```

它沿用现有的安装配置，不卸载 Host，不清数据。`/var/lib/aru-selfhost/provider-secrets` 里的 `master.key` 是解开已保存 Key 的唯一钥匙，备份机器时请把这个目录整体保留。
