# Aru Host 0.31.2

这次主要修复备份上传，以及 Windows / Linux Console 的几个问题。

- 修复新版 Aru 加密备份上传时出现 `400 package.invalid_metadata`。Host 保存加密归档时接受合法的原生归档版本，恢复兼容性仍由手机端判断；加密包完整性与大小校验保持有效。
- Windows 手动重启与容器启用后的重启共用完整的停止流程，等待旧任务退出并清理该实例的子进程后再启动。
- 容器验证通过后，等待 Host 实际报告可用。就绪检查包含网络请求超时，失败提示区分服务未响应和服务仍报告不可用，不会把保存配置当成启用成功。
- 修复 Windows / Linux Console 协作者主动规则页面的请求被自身拦截。
- Windows 防火墙配置会检查提权进程的结果并重新读取规则，创建失败不再直接报告完成。

## 下载与升级

| 系统 | 安装包 |
| --- | --- |
| macOS 26+ | Apple 签名、公证的通用 DMG |
| Windows 10/11 x64 | 未签名预览版 EXE |
| Debian/Ubuntu x64、arm64 | 对应架构的 DEB |

每个安装包都有 `.sha256` 校验文件和 JSON 版本记录。Windows 仍可能出现系统信誉提示，不含 Windows arm64 安装包。

直接用新版安装包升级，无需先卸载或删除数据。Host 协议保持 `stub-0.30`，本次没有数据迁移。手机端版本不会随 Host 自动更新。

发布流水线验证四个平台安装包、Windows 任务与进程生命周期、Linux 容器任务，以及 macOS 签名公证。具体用户电脑上的容器环境仍需更新后复测。
