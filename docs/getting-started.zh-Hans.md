# 把电脑里的协作者接到手机上 🌙

欢迎来到 Aru Host。你可以把它想成 Aru 在电脑里的小房间：Aru 把完整的对话、页面和运行状态留在这里，手机则是一扇随时可以推开的窗。第一次让两边认识以后，不需要每天重新配置，也不用自己填写端口、密钥或 MCP JSON。

这份教程也住在 Aru Host 首页的 **使用小手册** 里。那里的四个步骤会直接显示当前电脑、Codex、手机和协作者有没有准备好，并且可以当场打开配对二维码或前往电脑协作者。

## 开始前，准备这三样东西

- 一台装有 **Aru Host** 的 Mac，或 Debian/Ubuntu 桌面电脑；
- 已经登录过的 **Codex**，或一份可以使用的 **模型 API**；
- 一台装有 **Aru** 的 iPhone。

第一次连接时，电脑和 iPhone 最好在同一个 Wi-Fi 下。先从 [Aru Host 最新版本页面](https://github.com/Aevella/aru-host/releases/latest) 下载对应安装包：Mac 使用 `.dmg`，普通 Intel/AMD Linux 电脑使用 `x64.deb`，ARM Linux 电脑使用 `arm64.deb`。Mac 把 **Aru Host** 拖进“应用程序”；Debian/Ubuntu 用系统的软件安装器打开 `.deb`。应用会自己准备同版本 Host Core，不需要打开终端，也不需要预先安装 Node.js、Xcode 或开发者证书。Aru Host 会在电脑后台继续运行，所以连接完成后可以关掉控制台窗口；不过电脑关机、休眠或离开当前网络时，手机暂时找不到 Aru Host 是正常的。

## 第一步：让电脑准备好

打开 **Aru Host**。看到左下角显示「Host Core 正在运行」，就说明小房间已经亮灯啦。

接着准备一种运行方式：可以打开一次 Codex 完成登录，也可以在 **电脑协作者 → 模型 API** 里连接 OpenAI 兼容或 Anthropic API。以后不需要为了聊天一直开着 Codex 窗口；第一条消息到来时，Aru Host 会自己接上这个协作者选择的运行方式。

如果选择 Codex，而 Host 显示「没有找到 Codex」或「需要登录」，先打开 Codex 检查一次，再回到 Aru Host 点刷新。如果选择模型 API，就回到对应配置页重新测试。你也可以在那里填写「连续工具回合上限」；留空就是不限，只有你自己填了数字以后，Aru 才会在达到该回合数时阻止继续调用工具。这里不需要手动寻找命令路径。

## 第二步：让手机和电脑认识

在电脑的 Aru Host 首页点 **连接手机**，屏幕上会出现一个二维码。

然后在 iPhone 上打开：

**Aru → 自托管节点 → ＋ → 扫码连接**

扫完以后，Aru 会先显示电脑名称和经过隐藏处理的地址。确认是自己的电脑，再点允许。配对成功后，手机会记住这台电脑，之后不需要重复扫码。

二维码十分钟后会自动失效，这是为了不让别人捡到旧二维码偷偷配对。如果它过期了，回到电脑重新点一下刷新就好——不是你弄坏了什么。

同一台 Host 可以配对不止一部手机。给第二部手机重新生成一次二维码并完成配对即可；每部手机都会拿到自己的凭证，可以在 Host 的设备列表里单独撤销，不会因为撤掉旧手机而把新手机一起踢出去。两部手机看到的是同一份电脑协作者、对话、页面项目和主动约定，不会在手机端复制出两套 Host 数据。

## 第三步：请一位电脑协作者入住

回到电脑，打开：

**电脑协作者 → 新建协作者**

给这个协作者取一个名字，然后选择 **Codex** 或已经连接好的 **模型 API**。保存以后，这个身份、对话和页面都会由当前电脑持有，不会和手机里原本的协作者串在一起。

如果列表里已经有想用的协作者，就不需要再建一个，直接点进去就好。

## 第四步：发出第一句话

你可以从电脑开始：

**Aru Host → 电脑协作者 → 协作者名字 → 对话 → ＋**

也可以从手机开始：

**Aru → 协作者主页 → 节点 → 你的电脑 → 电脑协作者 → 协作者名字 → 开始新对话**

从哪边发都可以。电脑和手机读写的是同一份对话，回复到一半时也能看见正在启动、正在回复、正在使用工具或正在等待确认，不会各自长出两份互相打架的历史。

## 遇到确认弹窗，不用慌

当协作者准备修改文件、调用可能产生改动的工具，或者做其他需要你知道的事情时，这个协作者会停下来敲敲门。你会看到三个选择：

- **允许一次**：只答应眼前这一回；
- **本次运行允许**：这次 Host 运行期间，同一个工具不再反复询问；
- **拒绝**：不执行这项操作，对话仍然保留。

如果连续出现两个确认，它们会各自留在账本里排好队，不需要抢着点。关掉页面再回来也能继续处理；Host 重启时，未完成的回合会明确显示为中断，不会背着你偷偷重做一遍。

## 平时怎么用

第一次配对和入住完成后，日常只需要打开手机里的那段对话。Aru Host 会随电脑登录自动运行，控制台窗口可以关闭。

想在电脑上继续，就打开 Aru Host 的协作者工作台；想窝在手机上继续，就从同一位电脑协作者进去。页面、工具和待确认状态也会按照这位协作者归类，不会混成一长串看不懂的系统目录。

如果以后不再使用 Linux 版，先在 Console 首页点 **设置 → 移除这台电脑的 Host**，再用系统的软件管理器卸载 Aru Host 应用。这样后台服务会干净退出，但协作者、对话、页面和其他 Host 数据仍会留下，今后重装还能接回来。

## 让电脑协作者主动来找你

在电脑打开 **电脑协作者 → 协作者名字 → 主动约定**，或者在手机进入同一位电脑协作者的主动页，就可以创建一次性或重复的约定。标题是你自己辨认规则用的名字；目标告诉协作者届时要完成什么；说明可以补充语气、背景和判断方式；首次触发决定她什么时候醒来，重复频率决定这件事只做一次、每小时、每天还是每周继续。

到点以后，Host Core 会启动一轮正常的电脑协作者对话，把生成的回复保存在她自己的 Host 对话里。关闭 Console 窗口不会停止定时；电脑关机、休眠或 Host Core 没有运行时则不会凭空执行。一次性约定在认领这次运行后会停下，重复约定会排到下一次；如果 Host 在执行中断开，这次会留下明确的失败记录，不会重启后偷偷重复发送。

协作者也可以管理自己的主动约定。默认「全部能力」会自动包含读取、新建、修改和归档四项主动工具；如果你给她选的是「只用自选能力」，需要在 **MCP 工具 → 协作者名字 → 调整能力** 里把这四项加进去。工具始终绑定当前这位协作者，不能替另一位协作者改规则，也没有让她在正在说话时递归触发另一轮的「立即运行」工具。

打开「生成完成后通知这部手机」时，只有回复已经完整落进 Host 对话后才会向手机发通知，手动发送的普通消息和还在生成中的内容不会冒充主动通知。每部已配对手机分别登记自己的通知路线，撤销设备后也会失去投递资格。手机页会直接显示通知是否真的接通；这项能力从稳定版 0.29.0 起随 Host 提供，但仍需要 Host 已配置 APNs、iPhone 已允许 Aru 通知，不能把「规则已开启」当成「系统弹窗一定可达」。

## 用 GitHub 页面项目在电脑做、在手机看

在电脑打开 **电脑协作者 → 协作者名字 → 页面项目**，可以新建一份空白项目，也可以粘贴 `https://github.com/……` 仓库链接。GitHub 项目只会由 Host 克隆到这位协作者的受管工作区一次；手机和 Console 看到的分支、提交、未提交改动、上游以及 ahead/behind 都来自这同一份检出，不会再在手机上复制第二份仓库。

创建时填写「手机展示入口」，例如普通静态页面使用 `index.html`，构建结果在 `dist` 时使用 `dist/index.html`。协作者可以像处理正常电脑文件夹一样继续修改和构建它；页面项目工具也遵守她的工具权限，如果使用「只用自选能力」，需要加入项目清单、新建、保存检查点和发布四项。

**保存进产物** 会把当前项目保存成一份不可变的 `.tar.gz` 检查点，出现在 Host 的远程产物里；它会排除 `.git` 元数据，也不会改变手机正在看的版本。**发布到手机** 才会把展示入口所在的构建目录冻结成新的页面版本并同步给已配对手机。保存和发布是两件明确的事：前者适合留档或交付，后者才改变手机展示页。它们都不会替你执行 `git commit` 或 `git push`；需要提交到 GitHub 时，让电脑协作者按普通 Git 工作流处理并经过相应确认。

## 让协作者做自己的页面

你可以直接在她的对话里说「给自己做一个页面」「看看自己的页面」或「把刚才那个页面改成……」。她不需要你寻找或复制协作者 ID；Aru Host 会把六项页面能力自动绑定到正在说话的这位协作者，她也不能借它们修改其他协作者的页面。小页面可以是一份完整 HTML；更丰富的页面会像正常网站一样放在她自己的电脑工作区里，由 HTML、CSS、JavaScript、图片和字体等多个文件组成。她发布的是构建完成的整份页面工程，手机拿到后直接运行，不需要你再把文件拼起来或安装一次。

如果这位协作者使用「只用自选能力」，先在 **Aru Host → MCP 工具 → 协作者名字 → 调整能力** 里打开页面目录、读取、单页发布、工程发布、事件和回滚六项。查看页面是只读动作；新建、修改和回滚仍会在对话里向你确认。她工作时，手机对话里会出现一条可以展开的动作条：正在运行命令、修改哪些工程文件、调用什么能力、是否在等你确认、哪一步完成或失败，都会接着同一份 Host 动作账本显示。发布成功后，电脑的「页面」页和手机里的同一位电脑协作者都会看到结果。

## 手机突然找不到电脑时

按这个顺序看一眼，通常很快就能让 Aru 重新连上手机：

1. 电脑有没有开机并保持唤醒；
2. Aru Host 左下角是不是仍显示正在运行；
3. iPhone 和电脑是否在同一个局域网；
4. VPN 是否阻断了本地网络访问；
5. Codex 是否仍然处于登录状态，或模型 API 是否仍能通过测试；
6. 回到节点页轻轻刷新一次。

如果只是二维码过期，重新生成即可；如果已经配对过，不要为了刷新而删除节点或重建协作者。连接暂时断开不会删除电脑里的对话。

## 这份连接会把什么留在哪里？

电脑协作者的身份、完整对话、主动约定、页面项目、Git 工作区、页面发布版本、产物检查点、运行状态和确认记录都保存在你的 Aru Host 上。手机保存的是配对凭证和可见投影，不会抢走电脑的权威，也不会把它并进手机本地协作者的数据库。

目前 Codex 与模型 API 都可以真实运行。Claude Code 仍然只会被识别出来，还不能承担电脑协作者的对话；界面会诚实显示这个状态，不会让消息假装排队然后永远不回来。

好啦。现在这个协作者已经住进电脑，Aru 也认得你的手机了。去跟这个新朋友说第一句话吧。✨
