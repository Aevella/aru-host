# Aru Host 0.34.1

这一版修复 Mac 更新后容器配置被覆盖的问题，并补齐远程连接地址的设置入口。

- 更新保留已经配置的容器引擎路径、镜像及资源设置，不再因为安装进程找不到命令或引擎暂时没有启动而改成“未配置”。容器是否真正可用仍由 Host Core 的运行检查决定；Mac Console 会区分检查中、未配置和配置已保留但暂时不可用。
- Mac Console 的“概览 → 节点设置”可以添加、检查和移除 Tailscale 或公网 HTTPS 地址。保存后，Host 立即把这些地址与原局域网地址一起提供给手机，重启后仍然保留。
- 连接检查只读取公开 Host 清单并核对身份，不向未验证地址发送配对凭据。Mac 能访问不等于手机能访问，手机仍需要相应的 Tailscale 或 HTTPS 连接条件。

## 更新和使用

Mac 用户下载 DMG，替换应用后打开“概览”，按提示更新 Host Core，再进入电脑名称旁的“节点设置”。不必先卸载，不要删除原数据目录。独立安装的 Host Core 仍由原安装方式管理；更新手机 App 不会替电脑更新 Host。

填写已经可用的 Tailscale 地址（例如 `http://100.100.100.100:8787`）或公网 HTTPS 地址，不带路径、账号或密码。点击“检查连接”后保存。这个版本提供手动添加入口，没有自动检测 Tailscale，也不会自动配置隧道或反向代理。

如果旧版本已经把容器配置覆盖成未配置，新版本不能凭空恢复原路径；启动 Docker 或 Podman 后，在“运行环境”重新验证一次。之后的更新会保留该配置。

0.33.1 的安装路径引号问题已在 0.34.0 修复，本版保留该修复。Windows 与 Linux 同步发布匹配版本的 Host Core，新的原生设置入口位于 Mac Console；Windows 安装包继续作为未签名 preview 提供。

## 验证范围

本机发布前检查：核心 112 项通过、1 项平台跳过；Mac Console 44 项通过；生成运行包检查、Mac 安装升级检查和 HTTP smoke 通过。真实独立 Core 进程验证了授权后保存、立即发布、重启保留、冲突拒绝与删除地址；安装器验证了引擎不可用时保留带空格的原路径、镜像与内存设置。实际 SwiftUI 本地测试窗口验证了保存、取消和重新打开。

正式安装包由发布流水线执行 macOS Developer ID 签名、公证与 Gatekeeper 检查，以及 Windows/Linux 安装检查和最终资产校验和检查。以上本机证据不代替反馈者设备上的升级与手机远程连接验收。
