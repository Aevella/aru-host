# Aru Host 0.31.0

这次更新让手机协作者更容易使用自己的电脑，并把可选运行环境的安装步骤接起来。

## 下载哪个安装包

| 设备 | 下载文件 | 发布状态 |
| --- | --- | --- |
| Mac（macOS 26，Apple Silicon / Intel 通用） | `aru-host-macos-0.31.0.dmg` | Developer ID 签名与 Apple 公证 |
| Windows 10 / 11，x64 | `aru-host-windows-0.31.0-x64.exe` | **预览版，尚未代码签名** |
| Debian / Ubuntu 桌面，x64 | `aru-host-linux-0.31.0-x64.deb` | 桌面安装包 |
| Debian / Ubuntu 桌面，arm64 | `aru-host-linux-0.31.0-arm64.deb` | 桌面安装包 |

每个安装包都有同名 `.sha256` 校验文件和 JSON 版本记录。Windows 预览包可能出现系统信誉提示；它还不具备可验证发布者的代码签名。当前没有 Windows arm64 安装包。

## 更新

- 新增 Windows 当前用户安装包、后台服务、手机配对、Windows 凭据保护和防火墙设置入口。关闭 Console 后，Host 后台服务继续运行。
- 手机协作者可以在 Host 建立自己的项目与页面身份，不再要求电脑先配置模型 API 或 Codex。需要支持此功能的新版 Aru 手机客户端；电脑协作者原有模型配置和数据保持独立。
- Mac、Windows 和 Linux 桌面的总览与运行环境新增“脚本与容器插件 · 可选”。基础文件、网页发布和手机配对不依赖容器。

## 修复与说明

- 修复 Windows 首次启动的桌面桥接、配对日志占用和长路径清理问题。
- 节点状态明确说明容器字段的含义，避免把“未配置容器”误认为整个 Host 不可用。
- 保留旧版固定文件清单安装器的 Host 启动和手机身份接入能力。命令行用户若要使用新的容器接入命令，请先重新运行当前安装器；桌面用户直接更新应用即可。

## 怎样启用脚本任务

在 Host 的“运行环境”中打开官方安装说明，安装并启动 Podman Desktop，或使用已有的 Docker。然后回到 Host，点“检测并启用”。Host 会准备任务镜像，实际验证 Node.js、Python、Shell 与工作目录读写；全部通过后才启用。验证失败会保留原配置，并允许重试。

准备镜像需要网络和磁盘空间，可能耗时几分钟。成功后会重启 Host，并中断正在运行的工作，请选择合适的时间。Mac / Windows 的容器虚拟机由官方安装引导配置；Host 不会静默安装 WSL 或虚拟机。Linux VPS 的完整安装器继续自动准备 Podman 与任务镜像。

## 升级与验证范围

Mac 用新应用替换“应用程序”里的 Aru Host；Windows 运行新版安装包；Linux 安装对应架构的新版 `.deb`。常规升级沿用现有用户数据目录，不需要先卸载，也不需要重新创建协作者。重启后请确认手机仍能连接，再继续工作。

Host 协议保持 `stub-0.30`。版本变化不代表所有设备已自动更新。发布检查包含 Host HTTP/MCP、独立手机身份、旧载荷兼容、真实 Linux 容器运行、Mac 签名公证，以及 Windows 安装/配对/升级/回滚/卸载流程。Windows 容器虚拟机安装仍需在具体设备上完成官方引导，不能把 Linux 容器测试当成 Windows 虚拟机验收。
